# Security policy

## Reporting a vulnerability

Please report security problems privately, not in a public issue:

1. Open this repository's **Security** tab.
2. Choose **Report a vulnerability** (GitHub private vulnerability
   reporting).

Only you and the maintainer can see the report.

Please include:

- what the problem is and what an attacker could do with it;
- the steps to reproduce it, and the commit or build you tested;
- the Android version and device, if relevant.

Don't include your own notes, recordings, transcripts, to-dos, backup files
or encryption keys. Use made-up data to demonstrate the problem.

## What to expect

Xayra is maintained by one person, so responses are best effort. The
maintainer will try to acknowledge a report within a week, keep you
informed, and credit you when a fix is published if you'd like that. There
is no bug bounty.

Please give the maintainer reasonable time to fix a problem before
disclosing it, and don't access or change data that isn't yours while
investigating.

## Scope

In scope: the source code in this repository, on `main`. Xayra isn't
publicly released; it's in a testing phase.

Out of scope, please report upstream instead:

- vulnerabilities in third-party packages, unless Xayra uses them in an
  unsafe way;
- Google, Cloudflare, Hugging Face or Android platform services.

Reporting a vulnerability grants no rights to Xayra's code (see
[LICENSE](LICENSE)).
